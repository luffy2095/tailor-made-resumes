# Updates

The dossier is the only place facts live, so every update is a dossier edit, a changelog line, and an offer to rebuild.

| User says | Do |
|---|---|
| "I learned X", "I finished the course" | Move X from In progress to Systems actually used, at the level actually reached. In every open job's gap map, move X from LEARN to KNOW. Offer to rebuild those kits. Professional Development drops X, Core Competencies gains it. |
| "New job", "I got promoted" | Run the standard questions that changed (seniority, move type), then discovery for the new role only. Add the role. Show the changed part of the dossier for approval. |
| "I earned a certification" | Ask for the issuer and year. Add it under Certifications held. It may now appear on resumes. |
| "Change my resume style" | Update Preferences. Rebuild only when asked. |
| "Show me what changed" | Show `profile/changelog.md`. |
| "Status", "what did I apply to" | Show `jobs/ledger.md`. |

## Patterns across jobs

After each new gap map, count how often each LEARN item appears across `jobs/*/gapmap.md`. When the same item is LEARN in three or more jobs, tell the user it is now blocking applications and offer a topic sheet and a crash course for it.

## Reproducibility

Each job folder has `built-from.txt` with the dossier hash it was built from. Do not rebuild an application that was already sent unless the user asks; the PDF they sent should stay what they sent.
